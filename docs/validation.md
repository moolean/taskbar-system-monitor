# 2.0 验证记录

日期：2026-09-14。以下区分自动测试、真实桌面测试与尚未覆盖的场景。

## 普通测试

Windows 自带 C# 编译器构建成功，`--self-test` / `test.ps1` 返回 0。

- CPU 首次采样、正常计算、无时间增量、计数回退。
- 内存总量有效、占用比例在 0–100% 范围。
- 网速计数差分、零时间、计数回退、休眠式长间隔。
- 设置首次写入、原子替换、重新加载，含内容列表、字号、高度、主题、对齐、刷新间隔和首次运行标记。
- 无效设置值归一化、历史采样保留最近 120 项。
- 108 组布局：4 个 DPI（96 / 120 / 144 / 192）× 3 个字号 × 3 种对齐 × 3 种可用宽度。每组均绘制浅色 / 深色、验证项目边界不交叠且不侵入设置按钮。

`docs/taskbar-preview.png` 是代码渲染的示例数据，不是实时桌面截图。

## 真实桌面 AppBar 测试

在真实用户会话的 Explorer 桌面运行 `--appbar-test`，而非沙箱账户。主屏幕 2560 × 1440、DPI 120（125%）。

| 检查 | 结果 |
| --- | --- |
| 原始工作区 | `(0, 0, 2560, 1380)` |
| 默认 24 逻辑像素栏 | `(0, 1350, 2560, 30)`，工作区底部缩至 1350 |
| 最大化测试窗口 | 客户区未进入资源栏 |
| 连续定位 50 次 | 位置和预留高度无漂移 |
| 调整到 32 逻辑像素 | 栏变为 `(0, 1340, 2560, 40)` |
| 隐藏 | 工作区恢复至原始 1380 高度 |
| 再次显示 | 只申请一次正确的空间 |
| Dispose / 退出 | 工作区完整恢复 |

第一轮实测发现隐藏后再次显示没有重新申请空间：旧 Bounds 与目标相同，错误地跳过了 `ABM_SETPOS`。已增加独立的预留状态判断，修正后完整回归返回 0。

## 真实设置界面与安装流程

- 已打开实际面板和设置窗口，核对内容选择、主题、字体、高度、对齐、网卡、刷新频率、预览及保存 / 取消按钮。
- 在界面中勾选时间并隐藏资源栏，保存后 XML 正确包含 Clock 和 `dock=false`。
- 使用安装脚本优雅停止实例、重新构建、保留设置并启动。仅托盘启动时重复启动仍可唤起面板。
- 重启后重新进入设置，勾选状态保持；测试结束恢复 CPU / 内存 / 下载 / 上传和资源栏可见。
- 已登记当前用户开机启动项；**未实际注销或重启 Windows 测试登录启动**。

## 尚未实测的范围

Explorer 崩溃重启、全屏游戏、远程桌面重连、自动隐藏任务栏、跨屏热插拔与运行中修改系统 DPI，以及 Windows 10 的各类任务栏排列尚未覆盖。代码处理了部分系统通知，但不能据此宣称这些环境都通过验证。

当前设计固定主屏幕底部整行 AppBar，不是任务栏内部组件；这项布局边界不会用透明覆盖或裁剪 Explorer 来规避。
