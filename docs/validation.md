# 3.1.1 验证记录

## 2026-09-15 TLS 初始化修正

- 用户反馈“发现账户 / PROPFIND：网络连接失败”，截图本身没有具体 WebExceptionStatus，因此不能据此认定密码错误或唯一根因。
- 检查 3.1 发布 EXE，确认缺少 `TargetFrameworkAttribute`，尽管项目文件声明了 net48。直接 csc 编译没有生成 SDK 通常生成的目标版本标记，可能启用旧 TLS 兼容默认值。
- 同机系统网络工具确认飞书域名 DNS 可解析，HTTPS 无凭据请求返回 HTTP 401；这证明系统网络能连到认证层，不证明用户密码有效。
- 3.1.1 为两种构建路径统一加入 .NET Framework 4.8 目标属性。新增自检已通过：实际运行目标为 v4.8，`ServicePointManager.SecurityProtocol` 为 `SystemDefault`，证书验证回调未被替换。
- TLS 握手、证书信任、DNS、代理解析、连接失败及超时使用分开的安全错误说明，不记录认证头或密码。
- 单独的临时网络诊断 EXE 被系统拒绝启动且随后不可见；没有尝试关闭安全软件或绕过限制，临时诊断源码已移除。未获得该程序的 TLS 对比结果。
- 本轮构建没有重启用户填有尚未保存凭据的设置窗口；真实账户端到端同步需要保存后再升级验证。

## 2026-09-15 更新

- 已安装侧栏 + 分组卡片的新设置界面。检查常规、外观、工作追踪、数据连接页；底部预览 / 保存 / 取消固定，内容独立滚动。空凭据的“测试连接”会在卡片内显示提示，没有发送网络请求。
- 真实桌面回归确认默认不存在 `WS_EX_TOPMOST`；可选置顶开关生效，模拟全屏通知会让位，关闭置顶后再经历全屏 / 重新定位仍保持非置顶。最大化窗口、50 次定位无漂移、隐藏 / 显示 / 退出恢复检查全部通过。模拟通知不等同于全屏游戏实测。
- 新增模拟 CalDAV 服务测试，覆盖 principal → 相对 home → 相对 calendar → REPORT；响应内 HTTP 403 不作为空日程成功，错误显示请求阶段，裸域名自动补齐 HTTPS。
- 同源路径跳转保留请求方法和认证，先关闭上一响应再请求下一跳；跨源跳转仍被阻止。这一兼容分支尚未对真实飞书租户完成验证。
- 本次诊断读取到的实际配置仍为不含 `calendar` 节点的旧配置；因此**没有验证用户所述密码是否正确，也未复现真实服务器返回的同步失败**。需要用户在新连接页填入专用账户，点测试后提供具体阶段 / 错误码，不能声称日历已接通。
- 构建改为原子替换输出；安装在保留旧版备份后复制并校验 SHA-256，避开当前 MSIX 虚拟化目录的替换失败。公网位置仍未启用。

## 真实桌面 AppBar 测试

在真实用户会话的 Explorer 桌面运行 `--appbar-test`，而非沙箱账户。主屏幕 2560 × 1440、DPI 120（125%）。

| 检查 | 结果 |
| --- | --- |
| 原始工作区 | `(0, 0, 2560, 1380)` |
| 默认 24 逻辑像素栏 | `(0, 1350, 2560, 30)`，工作区底部缩至 1350 |
| 最大化测试窗口 | 客户区未进入资源栏 |
| 连续定位 50 次 | 位置和预留高度无漂移 |
| 调整到 32 逻辑像素 | 栏变为 `(0, 1340, 2560, 40)` |
| 隐藏 | 工作区恢复至原始 1380 高度 |
| 再次显示 | 只申请一次正确的空间 |
| Dispose / 退出 | 工作区完整恢复 |

第一轮实测发现隐藏后再次显示没有重新申请空间：旧 Bounds 与目标相同，错误地跳过了 `ABM_SETPOS`。已增加独立的预留状态判断，修正后完整回归返回 0。
