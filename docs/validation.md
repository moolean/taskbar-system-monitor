## 真实桌面 AppBar 测试

在真实用户会话的 Explorer 桌面运行 `--appbar-test`，而非沙箱账户。主屏幕 2560 × 1440、DPI 120（125%）。

| 检查 | 结果 |
| --- | --- |
| 原始工作区 | `(0, 0, 2560, 1380)` |
| 默认 24 逻辑像素栏 | `(0, 1350, 2560, 30)`，工作区底部缩至 1350 |
| 最大化测试窗口 | 客户区未进入资源栏 |
| 连续定位 50 次 | 位置和预留高度无漂移 |
| 调整到 32 逻辑像素 | 栏变为 `(0, 1340, 2560, 40)` |
| 隐藏 | 工作区恢复至原始 1380 高度 |
| 再次显示 | 只申请一次正确的空间 |
| Dispose / 退出 | 工作区完整恢复 |

第一轮实测发现隐藏后再次显示没有重新申请空间：旧 Bounds 与目标相同，错误地跳过了 `ABM_SETPOS`。已增加独立的预留状态判断，修正后完整回归返回 0。

Explorer 崩溃重启、全屏游戏、远程桌面重连、自动隐藏任务栏、跨屏热插拔与运行中修改系统 DPI，以及 Windows 10 的各类任务栏排列尚未覆盖。代码处理了部分系统通知，但不能据此宣称这些环境都通过验证。
